Findings
P0 — Oracle can write any starting value, any time

recordStartingBagValue takes an arbitrary uint256. Oracle or owner can overwrite it for any token, any epoch, with no expected-epoch check.
Effect: on-chain “starting bag” is not a commitment. ROI / tier can be forged if metadata trusts this number.
Fix before any public performance claims:

Pass expectedEpoch and revert on mismatch
Allow one write per epoch (or only if current value is 0)
Stop treating owner as an oracle (onlySnapshotOracle should be oracle only)
Keep owner/oracle/signer on separate keys; owner on a multisig before mainnet

P0 — Metadata URI is fully mutable, no freeze

Owner can point tokenURI / contractURI anywhere, anytime. Events exist, but a hot owner key still rewrites the collection.
Acceptable on testnet. Not acceptable as-is for a public collection unless you document “trusted metadata operator” and later add multisig + timelock, ideally content-addressed art.
P1 — X uniqueness is not lifetime uniqueness

After transfer the hash is freed. Same X can be bound to another token, or authorized to mint on a new wallet if mintSigner cooperates.
On-chain you have: one mint per wallet, one X per active token.

You do not have: one X per human forever.
That is fine only if the mint signer is treated as a trusted allowlist, not as proof of uniqueness.
P1 — No on-chain unbind / recovery

Compromised X stays glued until the NFT is transferred (and then the 7-day lock restarts). Threat model asked for a recovery path. There isn’t one.
P1 — adminMint bypasses X + EIP-712

Owner can mint to any unused wallet with no profile. Useful for testnet. Dangerous if that key is hot.
P1 — Pause is incomplete

While paused, owner can still approve / setApprovalForAll, change URIs, rotate oracle/signer, and withdraw. After unpause, pre-set operators can move unlocked tokens immediately.
Define that as intended, or pause approvals too.
P2 — challengeId is not consumed

It must be non-zero and signed, then it is discarded. Replay protection is only nonce + deadline. Either store/consume challenge IDs or drop them from the typehash to avoid a false sense of binding.
P2 — Global nonce map

usedMintNonces[nonce] is not per-wallet. Signer must never reuse a nonce across users.
P2 — Receiver can hold many NFTs

Lifetime cap is on minting, not ownership. Secondary market can stack warriors in one wallet. If the product promise is “one warrior per person,” the site/leaderboard must enforce that; the contract will not.
P2 — No Withdraw event

Funds can leave with no indexed log.
P2 — startingBagValue = 0 until oracle writes

Metadata must treat 0 as “uninitialized,” not “empty bag,” or every new owner looks like a flatline until the oracle lands.
P3 — Custom ERC-721, thin tests

Not using a battle-tested library. Tests never cover:

expired / wrong-signer / wrong-wallet EIP-712
nonce replay
pause blocking transfers
bag-value reset after a real transfer
successful withdraw
oracle overwrite of an existing snapshot
bind after transfer to a new owner

Local tests also deploy owner = oracle = signer, which the deploy script forbids. The suite does not exercise the intended production role split.
