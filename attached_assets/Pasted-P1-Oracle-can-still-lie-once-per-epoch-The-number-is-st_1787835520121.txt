P1 — Owner can still become the oracle

setSnapshotOracle is owner-only. A hot owner key can rotate the oracle to itself and write the next epoch.
Contract cannot fix that. Ops can: don’t use a single hot owner; don’t rotate oracle casually.
P1 — Public state cannot tell “not written” from “written as 0”

_snapshotWriteEpoch is private. snapshotOf returns startingBagValue = 0 in both cases.
You now allow a real zero write (good), but the metadata service will guess wrong unless it:

watches WarriorSnapshotRecorded, or
you add a public snapshotWriteEpoch(tokenId) / snapshotRecorded flag

Do that before metadata uses on-chain bag value.
